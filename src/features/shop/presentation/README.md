# Product presentation boundary

`types.ts` describes visual media and material/graphic treatment only. `ProductViewer` owns accessible input, asynchronous viewer loading and a persistent 2D fallback. `ThreeProductStage` owns the lazily loaded renderer and the three presentation families. `ProductNavigation` accepts neutral labelled options. None imports commerce, Shopify, money, inventory, variants or checkout.

`DropLab` is the separate demo orchestrator. Its typed source is `src/data/demoCatalogue.ts`, and every item has the literal `mode: 'demo'`. This catalogue has no prices, stock, variant identifiers or purchase destinations and must never be passed to Shopify purchase controls. `SHOP_MODE` defaults to `demo`; an unconfigured or unverified `live` request displays an unavailable store, never substitute demo inventory.

For future real products, `src/lib/commerce/productAdapter.ts` projects Shopify identities and explicitly assigned front/back media IDs into a presentation input. It prefers a Shopify GLB source, then glTF, and leaves absent rear media null. It contains no commercial values. Wire this projection to approved visual treatment and a reviewed GLB presentation family when actual optimized models exist; this real-store data/renderer integration is still pending. `ShopifyStorefrontIntegration` provides a separate, inactive browser-only purchase surface using Shopify's product context, variant selector, money and cart components. Shopify owns cart state and checkout. No custom cart provider or backend endpoints are required. See `docs/V5-SHOP.md` for setup, ownership and the live verification gate. `model3dAsset: null` truthfully records that no model files exist in this demo phase.

Apparel atlases contain actual distinct front and rear image regions. Graphic source, scale, color and vertical offset are data, not demo ID checks. Neutral backs have no invented official artwork. See `public/media/drop-lab/ASSETS.md` for asset provenance and prompts.

The input controller keeps pointer state outside React render state. Only deliberate Rotate enables horizontal pointer/touch inspection; vertical touch scrolling stays available. Front/Back use the nearest matching angle. Selection resets pose and sticker spread. The renderer uses a single canvas, low-complexity geometry, two small WebP atlases, bounded/adaptive DPR and a procedural soft contact shadow. Animation frames stop behind dialogs, on hidden pages and outside the exhibition. Cloned textures, procedural shadow textures, geometry/materials and the WebGL renderer are disposed on their owning lifecycle.
