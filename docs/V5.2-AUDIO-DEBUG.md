All six catalogue entries have null sources/durations and `enabled: false`; filtering produces an empty playable queue. There is consequently no music URL to request, decode, audition or validate for HTTP success.

Actual Chrome WITH SOUND clicks created one running AudioContext in an active user gesture, at 44.1 kHz. No music request occurred. Only the two original 0.42 s and 0.22 s procedural logo textures started. Volume was 35%, unmuted. The transport correctly reported `missing` and never showed NOW PLAYING. The error was easy to miss because its explanation lived inside the optional RADIO settings. Native Safari independently reproduced running context / zero sources / missing playback. These observations do not establish audible music playback.

The original visual MP4 has a 20.083333 s stereo 48 kHz AAC stream, and the 206.603333 s documentary MOV has stereo 48 kHz PCM audio. Neither is an identified, registered curated preview of ORIGINAL, KRITIKA, FANTASTIQUE, TIMALS, MACHI BATEL or BCP D’ARGENT. The optimized background and documentary web clips have no audio streams. No video audio was silently repurposed as an approved radio track.

## Architecture and changes

The existing shared locale layout contains one SoundProvider above VisualExperience, MusicProvider and all routes. It owns one lazy Web Audio AudioManager; RadioTransport shares that context and graph. Intro choice calls chooseMode synchronously before animation work; resume, when needed, is called in that same click stack. Intro completion only releases its effects. Client route changes do not replace the manager. Master gain is 0.35, music headroom 0.64, effects gain 0.08. No stuck mute, zero-volume output, duplicate provider, route unmount or rejected activation explained the observed absence of music.

Added development-only diagnostics for support, loaded source, context, transport state, volume and error. Missing inventory is explicit as `NO_PREVIEWS`; safe HTTP status/browser-denial/decode/duration/unlock-timeout errors survive instead of being reduced to a generic playback error. Missing sources also mark the existing RADIO trigger. Fixed a secondary state-reporting defect: an AudioContext constructed already running now publishes availability `ready` immediately. No new player, fake audio source or advanced crossfade implementation was added.

The existing bounded playlist, preloading, reviewed fades, persistence and media leases are retained. Cinema and controllable in-page media suppress local audio; closing requires explicit radio resume. Outbound provider links represent intent only, never inferred Spotify playback.
